# Markdown 阅读笔记规范

## 定位

把 `paper-notes.md` 写成简要、独立的摘要式研究记录，而不是 HTML 讲解的文字副本，也不是逐章翻译。默认追求精炼：保留结论、机制、证据和边界，删除教学铺垫、互动文案与重复解释。

## 推荐结构

按论文内容合并、拆分或改名，不要求每节等长。通常控制在约 1000–2500 个中文字符；复杂论文可以更长，但不要为了完整复述正文而扩张。

```markdown
# 论文标题

> 作者 · 会议/年份 · 论文链接 · 代码链接 · 阅读标签

## 一页速览
- 研究问题：
- 核心方法：
- 主要结果：
- 一句话判断：

## 核心贡献
说明解决的问题、相对已有工作的新增内容及成果。

## 方法与实现
用最短路径说明输入、核心模块、训练目标和推理过程。

## 实验证据
用表格整理数据集、基线、指标、主结果和消融。
解释每组数字支持什么结论。

## 局限与边界
区分作者明确承认的局限和阅读者推断的风险。

## 研究启发（可选）
只记录可复现、可验证或能形成研究问题的启发。
```

## 内容取舍

必须能够回答：

- 为什么需要这项工作？
- 方法最关键的新东西是什么？
- 具体如何训练、推理或实现？
- 哪些实验最能支持核心主张？
- 工作在哪些场景可能失效？

优先保留零至三个高价值图表。图片使用 `assets/figures/...` 相对路径，并在图注中写明来源与读图结论。没有合适图片时可以只用表格或代码原生教学图，但不要插入无内容的占位符。

## 公式与数字

- 忠实公式：保留原编号并标注章节或页码。
- 教学公式：明确写“直观化表达”，不要伪造原编号。
- 紧随公式定义符号并给出一句直观解释。
- 每个关键数字同时写清模型、任务、指标、比较对象和来源。
- 从图中估读的数值写“约”，不要伪装成精确结果。
- 只保留理解核心方法所必需的公式；详细逐式讲解放在 `index.html`。

## 事实层级

用自然语言或提示块区分：

- `论文报告`：作者直接陈述或实验直接显示。
- `阅读解读`：对机制和结果的解释。
- `延伸推断`：尚未被论文验证的假设或启发。

不要把“可能因为……”改写成确定因果。

## 图表规范

- 比较两个以上方法且字段重复时优先用 Markdown 表格。
- 流程图必须标注输入、转换、输出与反馈。
- 层级图必须标注边界和依赖方向。
- 实验图必须带轴、单位、图例和数据来源。
- 删除 `[图片]`、`TODO`、`TBD`、“暂时无法展示”等残留。

## 独立性检查

只阅读 `paper-notes.md` 时，读者应能复述论文的问题、方法、主要证据和局限。不要使用“如上图”“前面已经解释”等依赖 HTML 页面上下文的说法。
