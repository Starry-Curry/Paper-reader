# 论文讲解与图示设计

## 目标

让视觉表达降低论文理解成本。先确定读者需要理解的关系，再决定是否画图；不要先选组件再填内容。

## 内容主线

除非用户明确说明已有专业基础，先写出本页服务的“零基础读者问题”和必须补齐的先修概念。讲解优先按理解依赖组织，而不是照抄论文目录：

```text
为什么需要
→ 最小直觉
→ 正式定义
→ 公式怎样算
→ 算法怎样跑
→ 实验是否支持
```

按论文情况组织以下信息，不固定章节数：

- 问题与重要性；
- 旧方法的关键瓶颈；
- 核心洞察；
- 方法的输入、处理、状态和输出；
- 训练目标与推理路径；
- 实验证据；
- 局限与适用边界。

每一节先给结论，再给机制和证据。重复出现的背景只解释一次。

## 图示选择

| 需要解释的关系 | 首选形式 | 应包含 |
|---|---|---|
| 数据或算法按顺序流动 | 流程图 | 输入、处理、输出、反馈 |
| 组件包含、依赖或分层 | 层级图/架构图 | 边界、接口、方向 |
| 方法按阶段演化或逐步增强 | 递进图 | 每一步新增内容与收益 |
| 多方法或多配置重复比较 | 表格 | 一致字段、比较基准 |
| 指标随变量变化 | 曲线/柱图 | 轴、单位、图例、误差 |
| 事件随时间发生 | 时间线 | 仅保留影响本文的节点 |
| 简单定义或单一因果 | 文字 | 不强行配图 |

优先顺序：

1. 使用原论文图表作为证据。
2. 对原图加读图说明或局部标注。
3. 原图过于复杂时，绘制忠实的教学简图。
4. 只有拿到原始数值时才重绘结果图。

## 每张图的检查

- 能用一句话说明这张图回答的问题。
- 标题直接陈述图的用途，不写空泛标题。
- 图中术语与正文一致。
- 箭头有明确方向；颜色有明确含义。
- 原图注明 `Fig./Table + 页码`。
- 重绘注明“教学图”或“根据 Table/Fig. 重绘”。
- 图下解释“怎么看”和“它证明什么”。
- 不把推断画成论文已证明的因果链。

## HTML 表达

- 使用图示、表格、公式拆解和短段落的组合。
- 让关键信息在静态页面中也成立；动画只用于展示状态变化或顺序。
- 不强制时间线、方法对话、测验、卡片墙或悬停提示。
- 同一屏只突出一个核心关系。
- 正文、标题和公式保持统一字体层级；不要用字体变化代替信息结构。
- 为长图提供可放大视图，为表格提供移动端横向滚动。

## 事实边界

使用清晰标签区分：

- **论文报告**：正文、表格或实验直接给出的事实。
- **导师解读**：为了理解而加入的类比、分解或解释。
- **延伸推断**：论文没有直接验证的判断。

直观化公式不得沿用论文的公式编号。实验数字不得脱离模型、任务、指标、数据集或比较基准。
