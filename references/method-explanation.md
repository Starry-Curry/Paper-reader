# 方法、算法与公式讲解规范

## 目标

让读者能够沿着数据和状态变化复述方法怎样运行，而不只是记住模块名称和最终结论。除非用户明确说明已有背景，默认从第一次接触该领域的读者出发。以下内容是理解检查，不是固定页面模板；只使用适合当前论文的部分。

## 讲解主线

方法型论文优先回答：

1. 整套系统接收什么，输出什么？
2. 论文新提出的部分在哪里？
3. 哪些组件来自已有工作，哪些被冻结或保持不变？
4. 一次训练迭代发生什么？
5. 一次推理、采样或解码发生什么？
6. 关键公式分别位于哪一步？
7. 实验如何隔离并验证关键设计？

## 系统边界

先画清边界，再解释内部模块：

- 论文提出的组件；
- 直接复用的组件；
- 训练时使用但推理时不用的组件；
- 推理时新增的搜索、采样或 guidance；
- 数据预处理和最终后处理。

不要把整套系统的成绩全部归因于论文新增模块。

## 输入、输出与张量

至少选择一个论文中的具体配置，记录关键状态：

| 字段 | 内容 |
|---|---|
| 名称与符号 | 论文中的叫法 |
| shape | 明确 batch、token、channel 或空间维度 |
| 来源 | 数据、前一模块或随机采样 |
| 内容 | 该张量携带的信息 |
| 去向 | 下一步输入到哪里 |

如果 shape 是根据论文配置推导的，标记为“教学推导”；不要伪装成原文直接报告。

## 训练流程

以一次训练迭代为单位说明：

1. 读取什么样本；
2. 做什么预处理；
3. 是否采样噪声、时间步、掩码或负样本；
4. 网络看到哪些输入；
5. target 从哪里来；
6. 每个 loss 项约束什么；
7. 哪些参数更新，哪些冻结；
8. 是否更新 EMA、缓存或其他状态。

复杂方法提供短伪代码。伪代码中的变量必须在正文或符号表中解释。

## 推理或采样流程

以生成或预测一个结果为单位说明：

1. 初始输入或初始状态；
2. 是否存在循环；
3. 每步调用哪些网络；
4. 条件怎样进入；
5. 如何选择、采样或解码下一状态；
6. 何时停止；
7. 怎样得到最终输出；
8. 与训练流程有什么不同。

不要把“一次网络前向”和“完整生成过程”混为一谈。

## 公式卡片

先画出公式依赖关系，并把公式分为锚点、桥接和记账三层。锚点公式必须执行 [formula-tutorial.md](formula-tutorial.md) 的完整精讲协议；桥接与记账公式可以按重要性压缩，但不能断开方法主线。

每个关键公式紧邻解释：

- `来源`：原论文公式、等价变形、直观化表达或教学化重写；
- `位置`：训练、网络前向、推理或评测；
- `作用`：这一步解决什么问题；
- `符号`：每个符号的含义；
- `输入输出`：公式前后分别得到什么；
- `形状`：必要时说明维度；
- `直觉`：极端值、几何意义或最小例子；
- `代码对应`：论文或代码提供时再写。

非原文公式不得沿用论文编号。推导中添加的假设必须明确指出。

“解释过公式”不等于列出符号表。读者至少应能说出公式为什么出现、从哪里得到输入、算出什么、怎样影响训练或推理，并完成一个标量或低维的手算例子。

## 实验回扣

解释完模块后，用最有辨识力的实验回答：

- 移除它会怎样；
- 换成替代方案会怎样；
- 比较是否控制了其他变量；
- 结果支持的是相关性、有效性还是因果解释；
- 最佳成绩是否依赖额外技巧、采样预算或后处理。

## 完整性检查

读完讲解后，读者应能回答：

- 方法的新东西具体在哪；
- 一个样本如何从输入走到输出；
- 训练监督从哪里来；
- 推理为什么能工作；
- 关键公式在流程中各做什么；
- 论文证据支持了哪些设计判断。
